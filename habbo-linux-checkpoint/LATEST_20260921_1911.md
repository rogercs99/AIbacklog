## Most important current result
The sandbox kernel does not natively execute i386 ELF (`CONFIG_IA32_EMULATION` effectively unavailable). Pure Wine32 therefore returns Exec format error when run directly.

A fully local workaround now WORKS:

    PRoot 5.4.0 -> qemu-i386-static 7.2.0-1 -> Wine 5.11 staging 32-bit

Critical env flag:

    PROOT_FORCE_FOREIGN_BINARY=1

Without that flag, PRoot assumes i386 is compatible with x86_64 and skips QEMU, which fails on this sandbox kernel.

Evidence already achieved locally:
- `PROOT_PE32_OK` from a Windows 32-bit `cmd.exe` under PRoot/QEMU/Wine32.
- A REAL GUI window (Wine Notepad) rendered inside local Xvfb. See `logs/notepad-x11.png`.
- Therefore the 32-bit Windows GUI execution layer is solved in principle.

## X11 gotcha already diagnosed
An earlier process check incorrectly matched the string `Xvfb :99` inside its own shell command and falsely concluded Xvfb was running. The corrected path is to verify a real X socket/process, e.g. `/tmp/.X11-unix/X99`, not `pgrep -f` with a self-matching expression.

PRoot must expose the X11 socket to the Wine rootfs. Bind `/tmp/.X11-unix` (and host fonts if needed). After correcting this, Notepad rendered successfully.
